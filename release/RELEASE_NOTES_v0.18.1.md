# Jangbogo v0.18.1

**출시일**: 2026-08-07

이번 릴리스는 **v0.10.2 이후 누적된 약 40회의 main 푸시(v0.11.0 ~ v0.18.1)를 정식 배포로 묶은 버전**입니다. 기간이 긴 만큼 변화가 큽니다.

전반부(v0.11 ~ v0.15)의 주제는 **조용히 실패하던 것들을 드러내고, 실패해도 데이터를 잃지 않게 만드는 것**이었습니다. FTP 전송에 실패한 주문이 삭제되던 경로, 이마트 영수증이 바코드를 못 읽어 통째로 버려지던 경로, 셀렉터가 깨져 0건을 받아도 '성공'으로 기록되던 판정이 여기서 정리됐습니다.

후반부(v0.16 ~ v0.18)는 **비밀번호를 저장하지 않고 수집하는 경로**를 만드는 작업입니다. 사람이 브라우저에서 직접 로그인하고 그 세션을 암호화해 저장한 뒤, 수집 때 그것을 다시 넣어 쓰는 방식입니다. **이 기능은 기본적으로 꺼져 있으며 이번 릴리스에서 자동으로 켜지지 않습니다** — 아래 "세션 로그인 기능에 대하여"를 읽어 주세요.

DB 스키마는 앱이 기동할 때 자동으로 맞춰지므로 **기존 사용자는 제자리 업그레이드가 가능합니다.**

## 업그레이드 전에 알아 두실 것

기존 v0.10.x 사용자가 **체감하게 되는 동작 변화**입니다. 고장이 아니라 의도된 변경입니다.

| 무엇이 달라지나 | 왜 |
|---|---|
| **자동수집 주기 하한이 360분으로 강제됩니다** *(v0.11.2)* | 짧은 주기는 같은 계정으로 반복 로그인해 쇼핑몰의 차단을 자초합니다. 기존에 더 짧은 값이 저장돼 있으면 경고를 남기고 하한으로 올려 스케줄합니다. |
| **수집이 스스로 멈출 수 있습니다** *(v0.12.0)* | 같은 수집기가 연속 3회 실패하거나 실패가 48시간 이어지면 자동 차단하고 24시간 뒤 한 번 복귀를 시도합니다. 실패하는 사이트를 계속 두드리지 않기 위한 것이며, **사용자가 켜 둔 자동수집 설정 자체는 건드리지 않습니다.** |
| **브라우저가 한 번에 하나만 뜹니다** *(v0.15.1 · v0.15.9)* | 여러 몰이 같은 시각에 몰리면 뒤의 몰이 자리를 기다립니다. 오래 기다리면 그 회차는 건너뛰고 다음 주기로 넘깁니다. |
| **쇼핑몰이 받는 브라우저 정보가 바뀝니다** *(v0.15.7)* | 코드에 박혀 있던 옛 Chrome 버전 문자열을 지웠습니다. 이제 그 PC에 실제로 설치된 Chrome 버전이 그대로 나갑니다. |
| **'신규 주문 없음' 상태 파일 형식이 바뀝니다** *(v0.11.5)* | 수신측이 배열을 기대하는데 객체를 보내고 있어 매번 실패 처리되고 있었습니다. 이제 빈 배열을 보냅니다. |
| **개발용 엔드포인트가 사라집니다** *(v0.14.0)* | 주문·아이템을 통째로 지우는 `/dev/reset-database` 등이 운영 실행에서는 등록되지 않습니다. |
| **즉시수집이 건너뛸 때 계정 연결을 끊지 않습니다** *(v0.18.0 · v0.18.1)* | 예전에는 건너뛴 이유가 무엇이든 계정 상태를 초기화해, 수집에 성공한 몰까지 화면에서 '연결 끊김'으로 그려지고 있었습니다. |

## 주요 변경사항

### ✨ 새로운 기능

- **수집기 서킷 브레이커** *(v0.12.0)* — 반복 실패하는 수집기를 자동으로 차단하고 일정 시간 뒤 복귀를 시도합니다. 차단 상태는 DB에 남아 앱을 다시 켜도 유지됩니다.
- **수집기 건강도 경보** *(v0.13.0 · v0.14.0)* — 수집기별로 차단됨·오래됨·데이터 없음·한 번도 안 돎을 판정해 대시보드 '실행 결과 요약'에 배너로 띄웁니다. 정상일 때는 아무것도 그리지 않습니다. `GET /api/collect-health` 로도 조회할 수 있습니다.
- **FTP 전송 실패분 보류 큐** *(v0.11.0)* — 업로드에 실패한 전송분을 `pending/` 에 보관했다가 다음 회차에 오래된 것부터 재시도합니다(최대 50건 / 14일).
- **마지막 저장·마지막 전송 시각 분리 표시** *(v0.13.2)* — "파일은 저장되는데 전송만 죽은" 상태를 구분할 수 있습니다.
- **세션 로그인(브라우저로 직접 로그인)** *(v0.16.0 ~ v0.18.1)* — 계정연결 모달에서 브라우저를 띄워 직접 로그인하면 그 세션을 암호화해 저장합니다. 쿠키 값과 암호화 키는 로그·화면·응답 어디에도 남지 않습니다. **기본 꺼짐.**

### 🐛 수집이 실패하던 문제들

- **이마트 영수증이 조용히 사라지던 문제** *(v0.13.5 · v0.13.9)* — 바코드를 못 읽으면 경고 없이 버려졌고, 빈 바코드는 이마트 수집 전체를 실패시킬 수 있었습니다. 이마트가 영수증 화면을 개편하면서 새 템플릿이 섞여 내려온 것도 원인이었습니다. 실계정 검증에서 **17건 수집 → 17건 저장, 스킵 0건**을 확인했습니다.
- **전송에 실패한 주문이 삭제되던 문제** *(v0.11.0)* — 전송 파일은 그 회차의 신규 주문만 담은 증분이라 다음 회차가 대신 보내주지 않는데, 실패하면 지워지고 경고 한 줄만 남았습니다.
- **0건을 받아도 성공으로 기록되던 문제** *(v0.13.0)* — 셀렉터가 어긋나 빈 목록이 와도 성공으로 남았고, 브레이커의 실패 카운트까지 초기화해 **셀렉터가 깨져도 영구히 조용해지는** 상태였습니다.
- **수집 한 회차가 6분간 붙잡히던 문제** *(v0.13.4 · v0.13.6)* — 페이지 로드 제한 시간이 설정된 적이 없어 기본값 300초가 걸렸습니다. 60초로 명시했습니다.
- **진단 정보가 통째로 사라지던 문제** *(v0.11.4)* — 사이트가 알림창을 띄우면 드라이버가 그것을 먼저 닫아 버려 실패 문구·주소·스크린샷이 전부 유실됐습니다.
- **이마트 한쪽이 죽으면 다른 쪽 결과까지 버려지던 문제** *(v0.13.4)*, **오류 요약 칸이 1,000자가 넘는 진단 블록으로 오염되던 문제** *(v0.13.3)*, **건강도 배너가 조회 실패 시 옛 내용을 그대로 두던 문제** *(v0.14.0)*.
- **로그인 상태를 잘못 판정하던 문제** *(v0.18.0)* — 로그아웃 상태에서도 로그인된 것으로 읽었습니다. 사이트가 로그아웃 버튼을 화면에서 감춘 채 문서에는 남겨 두기 때문입니다.

### 🔒 보안

- **SQL 주입 지점 제거** *(v0.14.0 · v0.17.0)* — 수집한 페이지에서 온 값(영수증 번호·상품명 등)이 질의문에 그대로 조립되고 있었습니다. 특히 숫자를 걸러 낸다고 있던 처리가 **거르는 것이 아니라 깎는 것**이라, 잘못된 값이 **다른 쇼핑몰의 정보를 열어 주는** 형태였습니다. 전부 안전한 방식으로 바꾸고, 같은 형태가 다시 들어오면 빌드가 실패하도록 검사를 추가했습니다.
- **개발용 파괴적 엔드포인트를 운영 실행에서 제외** *(v0.14.0)*.
- **암호화 키를 외부에서 지정할 수 있게** *(v0.14.0)* — 이 저장소가 공개돼 있어 기본 키도 공개돼 있습니다. `jangbogo.crypto.key` / `jangbogo.crypto.iv` 로 덮어쓸 수 있고, 기본값을 쓰면 기동할 때 경고를 남깁니다. **기본값 자체는 바꾸지 않았습니다** — 바꾸면 기존에 저장된 FTP 비밀번호를 읽을 수 없게 되며, 재암호화는 별도 과제로 남아 있습니다.
- **차단되는 회차에서는 비밀번호가 메모리에 오르지 않습니다** *(v0.15.9)*.
- **라이선스 전문이 배포 ZIP 에 포함됩니다** *(v0.13.10)* — 그동안 여러 버전이 `LICENSE`·`NOTICE` 없이 배포됐습니다. AGPL-3.0 제4조 요구사항입니다.

## 세션 로그인 기능에 대하여 (v0.16.0 ~ v0.18.1)

비밀번호를 저장하지 않고 수집하기 위한 기능입니다. **이번 릴리스에서는 꺼진 채로 배포되며, 켜지 않으면 기존과 완전히 동일하게 동작합니다.**

지금까지 만들어진 것은 사람이 브라우저에서 직접 로그인해 만든 세션을 암호화 저장하고, 수집할 때 그것을 다시 넣어 아이디·비밀번호 없이 회원 페이지로 들어가는 경로입니다. 세션이 만료되면 그것을 인지해 해당 쇼핑몰의 수집을 멈추고 다시 로그인하도록 알립니다.

**아직 실제 쇼핑몰 왕복 검증이 끝나지 않았습니다.** 그래서 기본값을 꺼짐으로 두었습니다. 켜는 방법과 시점은 검증이 끝난 뒤 별도로 안내하겠습니다. 지금 임의로 켜면 만료 판정이 잘못 나와 정상 수집이 멈출 수 있습니다.

## 호환성 및 업그레이드

- **Windows 10/11 x64.** Java 설치가 필요 없습니다(JRE 21 번들 포함).
- **DB 스키마는 자동으로 맞춰집니다** *(v0.11.8 이후)* — 앱이 기동할 때 실제 DB와 대조해 없는 테이블·컬럼만 추가합니다. 기존 데이터는 보존됩니다.
- **업그레이드 방법** — 기존 폴더의 데이터를 유지한 채 새 ZIP의 파일로 덮어쓰면 됩니다. 서비스로 등록해 쓰고 계시다면 **먼저 서비스를 중지**한 뒤 교체하고 다시 시작해 주세요.
- **되돌리려면** 이전 버전 ZIP으로 되돌리면 되지만, 새로 추가된 컬럼은 남습니다(옛 버전은 그 컬럼을 읽지 않으므로 동작에 문제는 없습니다).
