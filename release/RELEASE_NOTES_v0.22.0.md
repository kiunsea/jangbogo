# Jangbogo v0.22.0

**출시일**: 2026-08-25

이번 릴리스는 **v0.18.1 이후 누적된 판(v0.18.2 ~ v0.22.0)을 정식 배포로 묶은 버전**입니다.

주제는 하나로 모입니다 — **조용히 지나가던 것을 드러내고, 잃던 것을 잃지 않게 만드는 것.** 이번 기간에 고친 결함들은 대부분 오류를 내지 않았습니다. 경고 한 줄만 남기고 계속 진행하거나, 아예 아무 흔적도 남기지 않고 데이터가 사라지거나, 화면에는 성공이라고 떠 있었습니다. 그래서 **아무도 알아채지 못한 채 오래 지속됐습니다.**

특히 **jiniebox 로 보내는 구매 이력이 평문으로 나가고 있었고, 전송에 실패한 회차분이 사라지고 있었습니다.** 아래 "꼭 읽어 주세요" 를 먼저 봐 주세요.

DB 스키마는 앱이 기동할 때 자동으로 맞춰지므로 **기존 사용자는 제자리 업그레이드가 가능합니다.**

---

## 꼭 읽어 주세요

### 1. 암호화를 켜 뒀는데 평문으로 나가고 있었습니다 *(v0.21.0)*

`ftp_encrypt_enabled=1` 로 암호화를 요구했는데, 암호화가 실패하거나 Public Key 가 없으면 프로그램이 **조용히 평문으로 내려보냈습니다.** 전송 경로 셋(자동 수집 · 수동 내보내기 · 스케줄 수집)이 모두 같았습니다.

경고는 로그 한 줄뿐이었고 **화면과 응답은 "업로드 완료" 였습니다.** 전송 채널 자체도 평문 FTP 라, 강등은 곧 노출입니다. 실리는 것은 주문번호 · 상품명 · 구매일자입니다.

**이제 암호화를 켰는데 암호화할 수 없으면 보내지 않습니다.** 그 회차분은 보류함에 들어가고, 설정을 고치면 다음 회차에 암호문으로 나갑니다. 화면에도 사유가 뜹니다.

> **확인해 주세요** — 그동안 `ftp_encrypt_enabled` 를 켜 두셨다면, 계정 설정에서 **Public Key 가 실제로 들어 있는지** 확인해 주세요. 비어 있으면 지금까지 평문으로 나갔고, 이번 버전부터는 전송이 중단됩니다.

### 2. 전송에 실패한 구매 내역이 사라지고 있었습니다 *(v0.21.0 · v0.21.1)*

jiniebox 로 보내는 파일은 그 회차의 **신규 주문만 담은 증분**입니다. 다음 회차가 대신 보내주지 않습니다. 그런데 자동 수집 경로는 업로드에 실패하면 그 파일을 지웠고, **도달하지 못했다는 사실조차 어디에도 남지 않았습니다.**

이제 못 보낸 회차분은 `pending/` 에 보관했다가 다음 회차에 오래된 것부터 다시 보냅니다.

> 주문 자체는 이 PC 의 DB 에 남아 있습니다. 다만 그동안 **jiniebox 쪽에 도달하지 못한 회차가 있을 수 있습니다.** 수신측 기록과 대조가 필요하시면 확인해 주세요.

### 3. 저장된 FTP 비밀번호를 잠그는 키가 공개돼 있었습니다 *(v0.22.0)*

이 프로그램의 소스는 공개돼 있고, 비밀번호를 잠그던 키가 **그 소스에 그대로 들어 있었습니다.** 잠근 의미가 없는 상태였습니다.

이제 **설치본마다 다른 키를 자동으로 만들어 씁니다.** 처음 실행할 때 `config\jangbogo-crypto.key` 가 만들어지고, 저장돼 있던 비밀번호는 자동으로 그 키로 옮겨집니다. **운영자가 할 일은 없습니다.**

```
★ config\jangbogo-crypto.key 를 지우지 마세요.

  지우면 저장된 FTP 비밀번호를 다시 읽지 못해
  관리 화면에서 다시 입력해야 합니다.
  (다른 자료는 사라지지 않습니다)

  백업 대상입니다. db 폴더만 백업하고 이 파일을
  빠뜨리면, 복원한 뒤 비밀번호를 다시 입력해야 합니다.
  장비를 옮길 때도 db 폴더와 함께 옮기세요.
```

이 키가 막는 것과 못 막는 것을 분명히 해 둡니다. **막습니다** — 공개된 소스만 보고 비밀번호를 푸는 것, db 파일(백업본 등)만 새어 나간 경우. **못 막습니다** — 이 PC 의 파일을 통째로 가져가는 경우(키 파일도 같은 PC 에 있기 때문입니다).

### 4. 주문번호에 꼬리표가 붙어 나가고 있었습니다 *(v0.20.1)*

오아시스 주문번호 칸의 표기가 바뀌었는데(`주문번호 : 00-…`) 파서가 따라가지 못해, 꼬리표가 붙은 채로 저장·전송됐습니다. 수신측은 문자열을 그대로 견주므로 **같은 주문을 두 번 받았고, 그 주문의 아이템 수량이 두 배가 됐습니다.**

새 판부터는 표기가 정규화되어 저장·전송됩니다. **기존에 저장된 꼬리표 행은 그대로 두어도 중복이 나지 않습니다.** 표기만 맞추고 싶으시면 CHANGELOG 의 v0.20.1 항목에 한 줄짜리 SQL 이 있습니다(자동으로 돌리지 않습니다 — 사람이 보고 돌립니다).

## 업그레이드 전에 알아 두실 것

기존 v0.18.x 사용자가 **체감하게 되는 동작 변화**입니다. 고장이 아니라 의도된 변경입니다.

| 무엇이 달라지나 | 왜 |
|---|---|
| **암호화를 켰는데 암호화할 수 없으면 전송이 중단됩니다** *(v0.21.0)* | 예전에는 평문으로 강등해 보내고 "완료" 라고 표시했습니다. 이제 보내지 않고 사유를 화면에 띄웁니다. Public Key 가 비어 있으면 이 상태가 됩니다. |
| **`config\jangbogo-crypto.key` 파일이 새로 생깁니다** *(v0.22.0)* | 이 설치본 전용 암호화 키입니다. 프로그램이 자동으로 만들며, **지우면 저장된 FTP 비밀번호를 다시 입력해야 합니다.** |
| **하나로마트 수집 대상 사이트가 바뀝니다** *(v0.19.0 · v0.19.2)* | 하나로가 오프라인 거래내역을 별도 사이트(`nhhanaro.co.kr`)로 분리했습니다. 기존 수집기는 구 사이트만 보고 있어 매 회차 0건이었고, 그 0건은 실패로도 잡히지 않았습니다. |
| **SSG 가 마지막 수집일부터 조회합니다** *(v0.19.4 · v0.19.5)* | 예전에는 매 회차 "오늘 기준 최근 1개월" 고정이라, 앱을 한 달 넘게 쓰지 않으면 그 사이 온라인 구매가 영영 들어오지 않았습니다. 실사이트 검증에서 **묻혀 있던 15건**이 들어왔습니다. |
| **로그에서 개인 데이터가 사라집니다** *(v0.19.7)* | 세션 ID · 주문번호 전체 · 구매일자 · 매장명 · 상품명이 평문으로 남고 있었습니다. 형식만 남기고 가립니다. |
| **이관한 DB 의 이전 장비 경로를 되잡습니다** *(v0.20.0)* | 다른 PC 에서 옮겨온 `save_path` 를 그대로 쓰면 없는 경로가 조용히 새로 만들어져, 내보낸 파일이 엉뚱한 곳에 쌓였습니다. |

## 주요 변경사항

### 🔒 보안

- **평문 전송 강등 제거** *(v0.21.0)* — 위 "꼭 읽어 주세요 1" 참조. 전송 경로 셋의 판정을 한 곳(`FtpEncryptionGate`)으로 모았습니다.
- **설치본별 암호화 키 발급** *(v0.22.0)* — 위 "꼭 읽어 주세요 3" 참조. 기존 비밀번호는 자동으로 옮겨지며, 옮기는 도중에 프로그램이 꺼져도 잃지 않습니다.
- **로그의 개인 데이터 마스킹** *(v0.19.7)* — 세션 ID 는 가리지 않고 **아예 뺐습니다**(살아 있는 자격증명이라 일부만 남겨도 좁혀 들어갈 수 있고, 진단에 필요한 경우가 없습니다).
- **저장소·배포본으로 개인 데이터가 새는 것을 자동 검사** *(v0.18.2)* — 개발 중 유입된 구매 이력이 저장소나 배포 ZIP 에 실리지 않도록 빌드에서 잡습니다.

### 🐛 잃던 것들

- **전송 실패분 유실** *(v0.21.0 · v0.21.1)* — 위 "꼭 읽어 주세요 2" 참조. 보류함을 두 경로에 모두 물리고, 두 회차가 동시에 돌 때 같은 것을 두 번 보내지 않도록 잠갔습니다.
- **하나로마트 오프라인 거래내역 0건** *(v0.19.0)* — 대상 사이트가 옮겨 간 것을 따라갔습니다.
- **SSG 온라인 구매가 묻히던 문제** *(v0.19.4 · v0.19.5)* — 실사이트에서 15건이 실제로 들어왔습니다.
- **저장에 실패한 날짜가 다시 조회되지 않던 문제** *(v0.19.1)* — 같은 회차의 더 늦은 주문이 저장되면 다음 회차 시작일이 실패한 날짜를 지나가, 그 구간이 영영 조회되지 않았습니다.
- **한 번도 데이터를 받은 적 없는 수집기가 영원히 '정상' 으로 보이던 문제** *(v0.18.7)*.

### ✨ 그 밖에

- **이관 경로 자동 보정** *(v0.20.0)* — 다른 장비의 절대경로를 감지해 되잡고, 필요하면 DB 에서 파일을 다시 만듭니다. 판정을 좁게 잡아 사용자가 일부러 지정한 경로는 건드리지 않습니다.
- **전송 결과가 화면에 뜹니다** *(v0.21.0)* — 서버는 사유를 내려보내는데 화면이 읽지 않아, 전송이 거절돼도 "저장 완료" 만 보이던 자리를 고쳤습니다.
- **하나로마트 카드의 안내 주소 정정** *(v0.19.2)*, **모든 화면이 같은 판의 Bootstrap 사용** *(v0.19.3)*.
- **개발 스크립트가 `build/` 를 직접 지우지 못하게 막았습니다** *(v0.18.3 · v0.18.4)* — 배포본을 그 아래에 풀어 쓰는 관행이 있어, 빌드 산출물과 실제 수집 데이터가 섞여 있습니다. 실제로 한 번에 사라진 적이 있고 복구하지 못했습니다.
- **한국어 Windows 에서 배치 스크립트가 깨지던 문제** *(v0.18.5 · v0.18.6)*.

## 호환성 및 업그레이드

- **Windows 10/11 x64.** Java 설치가 필요 없습니다(JRE 21 번들 포함).
- **DB 스키마는 자동으로 맞춰집니다** — 앱이 기동할 때 실제 DB 와 대조해 없는 테이블·컬럼만 추가합니다. 기존 데이터는 보존됩니다.
- **업그레이드 방법** — 기존 폴더의 데이터를 유지한 채 새 ZIP 의 파일로 덮어쓰면 됩니다. 서비스로 등록해 쓰고 계시다면 **먼저 서비스를 중지**한 뒤 교체하고 다시 시작해 주세요.
  - `config\` 폴더는 배포 ZIP 에 없으므로 덮어쓰면서 사라지지 않습니다. 자동 생성되는 `jangbogo-crypto.key` 도 그 안에 있어 안전합니다.
- **되돌리려면** 이전 버전 ZIP 으로 되돌리면 됩니다. 다만 **v0.22.0 을 한 번이라도 실행한 뒤 되돌리면 저장된 FTP 비밀번호를 읽지 못합니다**(새 키로 옮겨졌기 때문입니다). 그때는 관리 화면에서 다시 입력해 주세요.
