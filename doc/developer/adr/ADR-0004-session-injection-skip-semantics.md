# ADR-0004 — 세션 주입 수집의 건너뜀 판정 3건 (5-9′)

- 상태: **확정**. 파일럿 1개 몰(ssg 온라인몰) 배선 시점의 결정이며, 두 번째 몰을 붙일 때 그대로 승계한다
- 일자: 2026-08-07
- 대상: Phase 5-9′ (세션 주입 기반 수집) · 5-10 (세션 만료 감지)
- 선행: [ADR-0001](ADR-0001-session-profile-reuse-t3.md) — 프로필 재사용이 아니라 **세션 이관**이 성립한다는 판정 /
  [ADR-0002](ADR-0002-session-capture-path.md) — 캡처를 후보 (a) 로 확정한 측정

## 배경

저장해 둔 세션을 브라우저에 주입해 **로그인 폼을 밟지 않고** 수집하는 경로가 배선됐다.
그 과정에서 판단이 갈리는 지점이 셋 있었고, 셋 다 **틀려도 예외가 나지 않는다** — 잘못 고르면 증상은
"수집이 조용히 0건" 이거나 "멀쩡한 세션인데 매 회차 건너뛴다" 로 나타난다. 로그만으로는 어느 쪽인지
구분되지 않는다.

세 결정은 지금 구현 클래스의 javadoc 에만 있었다. javadoc 은 **그 파일을 여는 사람**에게만 닿는다.
두 번째 몰(oasis·hanaro)을 붙이는 사람은 새 파일을 만들면서 같은 세 갈림길을 다시 만나는데, 그때
참조할 자리가 없으면 **각자 다르게 고른다.** 그래서 근거를 여기로 옮긴다.

javadoc 은 그대로 둔다 — 코드를 여는 사람이 문서를 찾아가지 않아도 되게 하는 것이 그쪽의 일이고,
여기 있는 것은 **대안을 왜 버렸는가**다.

## 확인한 사실 (코드)

| 확인 | 결과 |
|---|---|
| 스냅샷 부재·복호화 실패 | 예외가 아니라 **빈 스냅샷**으로 돌아온다 (`SessionSnapshotStore.load`) |
| 빈 스냅샷 주입 | **0** 을 돌려준다 (`SessionTransfer.inject`) |
| 요청보다 적게 반영됨 | 지금은 **경고 로그만** 남는다. 판정은 호출측 몫이다 |
| 캡처가 쓰는 프로필 이름 | `MallRegistry.mallId()` 를 디렉터리 이름으로 그대로 쓴다 (`SessionCaptureService.start`) |
| 마스킹이 걸리는 조건 | `WebDriverManager` 는 `profileDir` 이 null 이면 표식 제거도 `navigator.webdriver` 마스킹도 **하나도 달지 않는다** |
| 캡처 스냅샷의 범위 | CDP `Network.getAllCookies` — **도메인을 가리지 않고 전량**이다 |
| 인증 쿠키의 수명 | **세션 스코프.** 브라우저를 닫으면 사라지고 프로필에도 남지 않는다 (ADR-0001) |
| 건너뜀의 기록 통로 | `SessionCollector.Result.skipReason` → `MallOrderUpdater` 가 `SKIPPED` 행으로 적는다 |

## 결정 1 — 세션이 없으면 **건너뛴다.** 비밀번호로 폴백하지 않는다

빈 스냅샷을 만나면 브라우저를 **띄우지도 않고** `SKIPPED` 로 끝낸다.

### 왜 폴백이 아닌가

폴백은 겉보기에 친절하다 — 세션이 없으면 예전처럼 아이디·비밀번호로 로그인해 수집하면 되니까.
그런데 그러면 **화면에는 수집 성공으로 보이면서 매 회차 로그인 폼에 비밀번호가 다시 제출된다.**
이 프로젝트가 줄이려는 것이 정확히 그 반복 제출이다. 즉 폴백은 목적을 무너뜨리면서 **아무 로그도
남기지 않는다.**

더 나쁜 것은 그다음이다. 폴백이 걸린 상태에서는 아무도 "왜 세션이 없지" 를 묻지 않는다. 대시보드가
초록이기 때문이다. 그러면 세션 이관 경로는 **영원히 복구되지 않은 채** 코드로만 존재하게 된다.
조용한 실패의 교과서적 형태이고, 이 저장소는 이미 같은 형태로 2개월을 잃은 적이 있다.

건너뜀은 반대로 **신호를 남긴다.** 사유가 `jbg_collect_log` 에 SKIPPED 로 적히고 화면에 그대로
나가므로, 사람이 '브라우저로 로그인' 을 다시 눌러 복구할 수 있다. 그래서 사유 문자열은 원인이 아니라
**읽은 사람이 할 수 있는 일**을 가리키게 썼다.

### 부수 결정 — 스냅샷을 브라우저보다 **먼저** 읽는다

프로브는 드라이버를 먼저 띄웠다. 그것은 프로브가 "세션 파일이 있다" 는 전제로 도는 도구이기 때문이다.
무인 수집에서 가장 흔한 상태는 **'아직 캡처하지 않았다'** 이고, 드라이버를 먼저 띄우면 매 회차
브라우저를 띄웠다가 아무것도 못 하고 닫는다. `load` 는 DB·파일만 만지므로 앞으로 당겨도 이후 순서에
영향이 없다.

지켜야 하는 불변식은 하나뿐이다 — **대상 도메인 선방문이 주입보다 앞**이다. `about:blank` 상태에서
주입하면 일부 브라우저 버전이 **조용히 무시한다.** 이 한 줄이 빠지면 예외도 없이 로그인 화면으로 밀린다.

### 대안과 그것을 택하지 않은 이유

| 대안 | 왜 아닌가 |
|---|---|
| 비밀번호 로그인으로 폴백 | 목적이 무너지는데 로그가 남지 않는다. 대시보드가 초록이라 아무도 알아채지 못한다 |
| 예외로 올린다 | 위쪽 포괄 `catch` 가 계정 문제로 읽어 **계정 연결을 끊는다** — 이미 실제로 일어난 사고다(5-19). 세션 부재는 실패가 아니라 건너뜀이다 |
| 0건 SUCCESS 로 적는다 | 브레이커·건강도가 "정상인데 살 게 없었다" 로 읽는다. 세션 부재가 통계에서 지워진다 |

## 결정 2 — **부분 주입은 만료로 보지 않는다.** 만료는 '회원 페이지 도달' 로 가른다

`inject` 가 돌려주는 '되읽어 확인한 개수' 가 요청보다 적어도 **만료로 단정하지 않는다.**
가르는 것은 두 가지뿐이다.

| 신호 | 판정 |
|---|---|
| 반영 **0개** | 주입 자체가 성립하지 않았다 → 건너뜀 |
| `0 < 반영 < 요청` | **정상.** info 로그만 남기고 계속 간다 |
| 회원 페이지에 **도달하지 못함** | 세션 만료 → 건너뜀 |

### 왜 부분 주입이 정상인가

캡처는 CDP 로 **도메인을 가리지 않고 쿠키 전량**을 뜬다. 그래서 스냅샷에는 대상 몰과 무관한 호스트의
쿠키가 섞여 있고, 주입 시점의 도메인이 그것들을 거부하는 것은 **당연한 동작**이다. 이것을 만료로 읽으면
멀쩡한 세션이 매 회차 건너뛰어진다. 그리고 그 오판은 자기교정되지 않는다 — 사람이 세션을 다시 떠도
스냅샷 범위는 그대로라 같은 비율이 다시 나온다. **'다시 로그인하세요' 를 무한히 반복하는 화면**이 된다.

### 왜 도달 여부인가 — 그리고 왜 파싱보다 **앞**인가

만료는 이 축에서 실측 가능한 유일한 신호가 "회원 전용 페이지를 열었는가" 다. 다만 확인을 **파싱 뒤로
미루면 안 된다.** 만료된 세션은 로그인 화면을 주고, 그 화면에서 회원 페이지 셀렉터는 당연히 안 맞는다 —
증상이 **셀렉터 실패로 둔갑한다.** 그러면 사람은 '다시 로그인' 이 아니라 '사이트 구조가 바뀌었다' 를
뒤진다. 원인과 대응이 완전히 어긋난다.

**URL 에 회원 페이지 표식이 있다는 것만으로는 부족하다.** 만료된 세션을 로그인 페이지로 보내면서
원래 가려던 주소를 **되돌아갈 파라미터로 달아 주는** 몰이 있다(ssg 에서 확인된 동작이며, 프로브가 쓰던
판정 기준이 그대로 이것이다). 그러면 로그인 화면의
URL 안에도 회원 페이지 표식이 들어 있어, 표식만 보면 **만료를 도달로 읽는다.** 그래서 로그인 표식이
섞여 있으면 도달이 아니다.

⚠ 이것이 **두 번째 몰을 붙일 때 가장 먼저 실측해야 하는 값**이다. 지금 `MallRegistry` 에서 oasis·hanaro
의 세션 수집기 목록이 비어 있는 이유가 바로 이것이다 — 회원 페이지 URL 은 프로브가 알고 있지만
'로그인 화면으로 밀렸다' 를 가를 마커를 재지 않았다. **추측해 넣으면 만료를 정상으로 읽어 0건이
성공으로 굳는다.**

### 대안과 그것을 택하지 않은 이유

| 대안 | 왜 아닌가 |
|---|---|
| `반영 < 요청` 이면 만료 | 스냅샷이 전 도메인이라 **정상 상태에서도 항상 성립한다.** 세션 경로가 아예 안 돈다 |
| 몰별 인증 쿠키가 주입됐는지로 판정 | 이름이 확정된 몰이 하나뿐이다. 그리고 '주입됐다' 는 '서버가 아직 유효하다고 본다' 가 아니다 — 만료된 값도 주입은 된다 |
| 파싱 결과가 0건이면 만료 | 진짜로 산 게 없는 회차와 구분되지 않는다. 만료가 EMPTY 로 위장한다 |

## 결정 3 — 주입은 **캡처와 다른 프로필**을 쓴다 (`<몰id>-inject`)

주입용 드라이버도 프로필 경로를 넘긴다. 다만 캡처가 쓰는 디렉터리와 **같은 것을 쓰지 않는다.**

### 왜 프로필을 넘기는가 — 세션을 담기 위해서가 아니다

인증 쿠키는 세션 스코프라 **프로필에는 애초에 남지 않는다**(ADR-0001. 그것이 이 국면 전체의 출발점이다).
그런데도 넘기는 이유는 하나뿐이다 — `WebDriverManager` 가 `profileDir` 이 null 이면 자동화 표식 제거도
`navigator.webdriver` 마스킹도 **하나도 달지 않기** 때문이다. 즉 여기서 프로필은 저장소가 아니라
**마스킹 옵션의 스위치**다.

### 왜 캡처 프로필을 재사용하지 않는가

캡처 창은 **사람 페이스로 몇 분씩 열려 있다.** 그동안 주기 수집이 겹치면 Chrome 이
`"user data directory is already in use"` 로 죽고, 수집이 통째로 실패한다. 겹칠 창이 넓고, 하필 사람이
세션을 새로 뜨는 중일 때 터진다 — 복구하려는 행위가 수집을 죽이는 형태다.

별도 디렉터리를 쓰면서 **잃는 것이 없다.** 프로필에 담을 것이 애초에 없기 때문이다. 덤으로 사람이
로그인하는 프로필이 자동화 흔적으로 오염되지 않는다.

### 함께 넣은 것 — 기동 전 고아 브라우저 정리

ChromeDriver 는 chrome.exe 를 띄운 **뒤에** 핸드셰이크한다. 핸드셰이크가 깨지면 `quit()` 으로 닿을 수
없는 브라우저가 프로필 락을 쥔 채 남는다. 실측에서 **고아 하나가 이후 시도 전부를 막았다.**

이 디렉터리는 주입 경로만 쓰므로 "지금 이 경로를 문 크롬이 있다" = "이전 실패가 남긴 고아" 가 성립한다.
**캡처 프로필에서는 같은 전제가 성립하지 않는다** — 사람이 열어 둔 살아 있는 창일 수 있다. 프로필을
나눈 것이 이 정리 동작을 안전하게 만든 셈이다.

### 대안과 그것을 택하지 않은 이유

| 대안 | 왜 아닌가 |
|---|---|
| 캡처 프로필 공유 | 사람이 로그인 창을 열어 둔 동안 수집이 락 충돌로 죽는다. 공유해서 얻는 것이 없다(프로필에 세션이 없으므로) |
| 프로필 없이 띄운다 | **마스킹이 하나도 안 걸린다.** 봇 방어 사이트에 표식이 켜진 브라우저로 들어가게 된다 |
| 프로세스 경계 락으로 조정한다 | 부품(`MallProfileLock`)은 있으나 배선 비용이 크고, 락이 걸려도 그 회차는 어차피 못 돈다. 프로필을 나누면 경합 자체가 사라진다 |

## 되짚어야 할 조건

1. **두 번째 몰을 붙일 때** — 결정 2 의 '도달/로그인 마커' 는 몰마다 실측해야 한다. 추측 금지가 이 ADR 의
   가장 비싼 조항이다.
2. **세션 수명(5-17) 측정 결과가 나오면** — 만료가 잦다면 결정 1 의 '건너뜀' 이 사용자에게는 '기능이
   자주 죽는다' 로 보인다. 그때 바뀌는 것은 폴백 여부가 아니라 **재로그인 유도 UI** 쪽이다.
3. **캡처 스냅샷 범위를 대상 도메인으로 좁히면** — 결정 2 의 '부분 주입은 정상' 전제가 바뀐다. 다만 지금
   좁히지 않은 것은 어느 호스트가 인증에 필요한지 실측되지 않았기 때문이다.

## 관련 — 만료를 무엇으로 기록하는가

건너뜀은 `SKIPPED` 로 적고, 만료는 그 사유 코드(`SESSION_EXPIRED`)로만 표현한다. **새 status 를
만들지 않고**, 몰 단위 상태 컬럼에도 만료를 쓰지 않는다. 근거는 5-10 착수 시점의 결정 기록에 있다 —
요지는 (i) 별도 status 를 파면 실패 로그 조회와 집계 두 곳을 다 고쳐야 하고 안 고치면 만료가 화면에서
조용히 사라진다 (ii) 만료를 두 곳에 두면 갱신 주체가 없는 쪽 값이 굳는다, 이다.
