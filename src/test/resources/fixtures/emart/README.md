# Emart 영수증 파서 픽스처

`Emart.parseReceipt(String)` 이 받는 값 — 영수증 팝업의 `<pre>` 엘리먼트 텍스트 — 을 재현한 픽스처다.
`EmartReceiptParserTest` 가 이 디렉터리의 `.txt` 를 읽어 파싱 결과를 검증한다.

## 데이터 규칙 (Phase 2-3 마스킹 규칙)

**이 디렉터리의 모든 값은 합성이다. 실제 수집물을 마스킹한 것이 아니다.**

`kiunsea/jangbogo` 는 PUBLIC 저장소다. 실제 영수증은 상품명·수량·금액·구매일시·매장·바코드가 모두
들어 있는 구매 이력 그 자체이고, 부분 마스킹으로는 재식별 위험이 남는다. 그래서 실물을 마스킹하는 대신
**파서의 분기를 덮도록 손으로 지은 데이터**를 쓴다. 분기 커버리지는 실물과 동등하게 확보하면서
개인정보는 애초에 존재하지 않게 하는 것이 목적이다.

지켜야 할 것:

- 상품명은 `테스트` 접두 또는 명백한 가공어만 쓴다. 실제 상품명을 쓰지 않는다.
- 바코드·영수증번호는 `8800000000001` 처럼 자릿수만 맞춘 더미를 쓴다.
- 매장명·전화번호·사업자번호는 `이마트 테스트점` / `02-0000-0000` / `000-00-00000` 로 고정한다.
- 실제 수집물을 이 디렉터리에 넣지 않는다. 실물 분석이 필요하면 커밋하지 않는 로컬 경로에서 한다.

## 픽스처 목록

| 파일 | 덮는 분기 |
|---|---|
| `basic-4col.txt` | 표준 4열 행 (`arrSize == 4`) |
| `starred-5col.txt` | 선행 기호가 별도 컬럼으로 분리된 5열 행 (`arrSize >= 5`) |
| `wrapped-name-first.txt` | `combineExtraPattern01` — 상품명 줄 다음에 나머지 정보 줄 |
| `wrapped-data-first.txt` | `combineExtraPattern01` — 정보 줄 다음에 상품명 줄 |
| `discount-row.txt` | 단가에 `-` 가 있는 할인행 스킵 |
| `summary-rows.txt` | `cancelKeys` 합계·부가세 등 요약행 필터 |
| `empty-items.txt` | 구분선 사이에 아이템이 없는 영수증 |
| `short-row.txt` | 컬럼이 4개 미만인 행 (현행 동작을 고정하는 특성화 픽스처) |

## 영수증 형식

`parseReceipt` 는 `-----------------------`(하이픈 23개 이상) 을 세어 구간을 나눈다.

```
<머리말>                  ← 구분선 0개, 무시
------------------------- ← 1개
<항목명 행>               ← colNameRow
------------------------- ← 2개
<아이템 행들>             ← 파싱 대상
------------------------- ← 3개, 여기서 중단
<꼬리말>                  ← 읽지 않음
```
